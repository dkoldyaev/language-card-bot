# Технические требования и архитектура

## 1. Стек технологий
- **Язык**: TypeScript.
- **Платформа**: Node.js (версия 22+, `tsx` для dev-режима, `tsc` для продакшена).
- **Веб-фреймворк**: Express.js.
- **База данных**: PostgreSQL.
- **ORM**: Prisma ORM (используется для миграций и типизированного взаимодействия с БД).
- **Тестирование**: Vitest + Supertest.

## 2. Структура и Инфраструктура
- **Структура проекта**: Основной код приложения и конфигурации (package.json, src, prisma) находятся в директории `base/`. Корневая директория содержит общую документацию и оркестрацию (`docker-compose.yml`).
- **Контейнеризация**: Приложение собирается через multi-stage `Dockerfile` на базе `node:22-alpine` и запускается через Docker Compose.
- **Работа с БД**: В Docker-окружении приложение обращается к базе данных, запущенной на хост-машине (локалхост), используя адрес `host.docker.internal`.

## 3. API и Авторизация
- **Rest API**: Основной способ взаимодействия с сервисом. 
- **Версионирование**: Все эндпоинты маршрутизируются с указанием версии (напр., `/api/v1/`).
- **Авторизация**: Реализована при помощи JWT (JSON Web Tokens). Токен передается в заголовке `Authorization: Bearer <token>`.
- **Клиенты**: В текущей архитектуре сервис работает исключительно как API. Интеграция с Telegram-ботами или клиентскими приложениями происходит на их стороне.

## 4. Real-time уведомления (Mercure)
- **Шина сообщений**: Используется Mercure Hub для отправки Server-Sent Events (SSE).
- **Отправка данных**: Бэкенд делает POST-запросы к Mercure API для публикации событий. В полезной нагрузке сообщений всегда передается поле `version` (например, `version: 'v1'`).
- **Изоляция (Приватные обновления)**: Данные пользователей изолируются через персональные топики вида `http://localhost/v1/users/{username}/*`. 
- **Безопасность клиента**: Для прослушивания топика клиент должен получить с бэкенда специальный Mercure JWT-токен, в котором поле `mercure.subscribe` ограничивает доступ только личным топиком пользователя.

## 5. Асинхронные задачи (В планах)
- Сервис изначально спроектирован с поддержкой асинхронного выполнения фоновых задач (например, парсинг словарей, переводы).
- Планируется интеграция полноценной очереди задач.
